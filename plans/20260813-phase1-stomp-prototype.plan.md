# 実行計画書: フェーズ1 最小プロトタイプ「着地禁止」モード

経緯: `product/` のフェーズ0で、現行企画は G1 不通過として落とした（`product/decisions.md` D4）。
20案から1案「着地禁止」が条件付きで生き残り（D9）、ワンシートまで書いた（`product/03-onesheet.md`）。
これはその案の**最小プロトタイプ**を作る計画である。

**この計画の目的は「面白いゲームを作ること」ではなく「面白いかどうかを判定できる最小の物を作ること」。**
判定に不要なものは、作れるとしても作らない。

## 1. 目的と完了条件

目的: 知らない人5人に説明なしで渡せる状態を、**実働2週間以内**に作る。

- 完了条件:
  - [ ] 既存4シナリオ（`run` / `boss` / `stage2` / `pause`）が**現行の基準ダイジェストのまま**通る
  - [ ] 新シナリオ `stomp` を追加し、`tools/replay-baseline.txt` に登録した
  - [ ] ブラウザで目視確認した（PC・スマホ両方）
  - [ ] 循環参照ゼロ
  - [ ] D9 の条件 C1・C2・C3 が実装に反映されている

**この最小形で答えを出す問い**（答えられないなら作った意味がない）:

1. 初見の5人が、説明なしにルールを理解するか
2. 落下が「自分のミス」に感じられるか、「理不尽」に感じられるか
3. 3分以内に1回はゴールに届くか（＝ D9 の C4）
4. スマホで片手プレイが成立するか（指が着地点を隠さないか）
5. **2週間で最小形に届いたか**（届かなければ、この案もコスト面で死亡と判定する）

## 2. 判断記録

| # | 論点 | 選択肢 | 採用 | 理由（却下理由を含む） |
|---|---|---|---|---|
| 1 | 既存ゲームをどう扱うか | 書き換える / 新モードとして足す / 別リポジトリに分ける | **新モードとして足す** | 書き換えると既存4シナリオの基準が全部無効になり、「壊したのか意図した変更なのか」が二度と区別できなくなる。モードを足して既存を素通しにすれば、**既存4本のダイジェスト不変がそのまま「壊していないことの証明」になる**。別リポジトリはエンジン資産（D2）を二重管理することになる |
| 2 | モードの持ち方 | グローバルなフラグ / 面データの `mode` フィールド | **面データの `mode`** | 面はすでにデータ駆動で、`stages/` に1ファイル足せば増える。モードを面の属性にすれば、面セレクトもリプレイのシナリオ指定も既存の仕組みに乗る。既定値は `'classic'` とし、既存2面は**1文字も書き換えない** |
| 3 | オートランの実装箇所 | `game.js` の移動処理を分岐 / `input.js` で入力を作り替える | **`input.js` で入力を作り替える** | `game.js` の物理を触ると既存の挙動に触れる危険が高い。入力段で「左右入力を捨て、常に右入力とみなす」1箇所のゲートにすれば、下流の物理は一切変わらない。**変更の影響範囲を1ファイルに閉じ込められる** |
| 4 | 「地面」の作り方 | 判定用の新しい仕組みを足す / `terrain` を空にして下端の死線だけ置く | **`terrain` を空にする** | タイル衝突のコードは `terrain` が空なら自然に何もしない。**新しいコードを足さずに「地面がない」が実現する。** 死判定は既存の落下死（画面外）をそのまま使えるか、使えなければ1行足すだけで済む。D9 の C3 そのもの |
| 5 | 踏んだ敵の扱い | 即消滅（現行） / 数フレーム潰れた足場として残す | **数フレーム残す**（C2） | 足場が即消えると一度戻れなくなり死のスパイラルになる。かといって消さないと倒す快感が消える。`entities/cat.js` に潰れフェーズを足す。**新しい敵の種類は増やさない**（増やすとコンテンツ量が増える） |
| 6 | 速度とコンボの連動 | しない / コンボ段数に応じて自動走行速度を上げる | **連動させる** | ワンシートの USP 3「上手いほど速く、派手になる」の実体。かつ難易度カーブを面の作り込みではなく**プレイヤーの上手さ側**に持たせられるので、面を増やさずに難易度が伸びる。極小規模と両立する唯一の難易度設計 |
| 7 | ジャンプの高さ | 固定 / 長押しで可変 | **長押しで可変** | 入力が1つしかない以上、そこに意思決定が乗らないとゲームにならない。既存のチャージショットが長押しを扱っているので、入力側の仕組みは流用できる |
| 8 | 敵の種類 | 既存5種を使う / 3種に絞る | **3種**（歩く・飛ぶ・踏めない） | 判定に必要なのは「足場が動く」「高さが変わる」「踏んではいけないものがある」の3つだけ。砲台・バネ・移動床は最小形の合否に関係しない。**使わない敵は面データに書かなければよい**ので、コードを消す必要はない |
| 9 | ボスを入れるか | 入れる / 入れない | **入れない** | トレーラー11コマ目の絵ではあるが、プロトタイプの5つの問いのどれにも関係しない。既存エンジンにボスはあるので、後から足せる |
| 10 | ローグライト要素 | 入れる / 入れない | **入れない** | D8 で殺した案。ここに忍び込ませると、面白さの原因が「着地禁止」なのか「能力選択」なのか分からなくなる。**検証の意味が消える** |
| 11 | リトライの挟み方 | ゲームオーバー画面を出す / 0.5秒以内に即再開 | **即再開** | ポータルは最初の30秒の離脱が全て。落下してから再開まで画面を挟むと、そこが離脱点になる |
| 12 | タッチ操作 | 既存の4ボタンを使う / 画面のどこでもタップ | **画面のどこでもタップ** | 入力が1つになるのでボタンを分ける理由がない。かつ「指が着地点を隠す」問題（レビューの失敗理由4）への直接の回答。D9 の C1 |
| 13 | 画面比を16:9にするか | いまやる / ポータル提出時にやる | **提出時** | ポータルの要件だが、面白いかどうかの判定には関係しない。プロトタイプ段階でやると2週間を圧迫する |
| 14 | 音 | 既存の合成音を流用 / 新規に作る | **流用** | 合否に無関係。ポータルは音が鳴らない状態で起動されることも多い |
| 15 | 新シナリオの検証範囲 | ゴールまで / 途中まで | **ゴールまで通す** | CLAUDE.md の罠「1面のボスは検証がそこまで届いていなかったので壊れたまま素通しした」。オートランなので入力列は短く、通し切るのが安い |
| 16 | 計測（死亡地点・リトライ回数） | 最小形から入れる / 後 | **後** | 5人の対面テストでは横で見ていれば分かる。計測が要るのは公開してからで、そのときは D6（ダイジェストを変えない）に従う |

## 3. 手順

各ステップの後に必ず `for s in run boss stage2 pause; do ... done` を回し、**既存4本が不変であること**を確かめる。
不変でなくなった時点で、そのステップの変更が既存に漏れている。

1. **面データに `mode` を足す**（既定 `'classic'`）。既存2面は書き換えない。
   この時点で既存4シナリオが不変であることを確認する（何も変えていないので当然だが、
   足場を固めてから進む）
2. **`stages/stomp1.js` を作る**。`terrain` は空、敵は歩く・飛ぶ・踏めないの3種だけ、
   `mode: 'stomp'`。長さは60〜90秒で終わる程度
3. **`input.js` にオートランのゲートを足す**（C1）。左右入力を捨て、常に右。ジャンプは長押しで高さ可変
4. **下端の死線**（C3）。`terrain` が空なので落下し続ける。既存の落下死で足りるか確認し、足りなければ1行
5. **踏んだ敵の潰れフェーズ**（C2）を `entities/cat.js` に足す
6. **コンボ連動の速度上昇**
7. **即リトライ**（0.5秒以内）
8. **タッチを画面全体に**
9. **新シナリオ `stomp` を `tools/replay-check.mjs` に足し、`replay-baseline.txt` に登録**
10. **ブラウザで目視**（PC・スマホ）。ここで初めて「意図どおりか」を人間が見る

## 4. やらないこと（明示的に捨てる）

ボス / ローグライト要素・能力選択・メタ進行 / 複数の面・面セレクト・セーブ / タイル地形の敷き込み /
ストーリー・演出の作り込み / ゴースト・リプレイ共有 / 16:9対応 / ポータルSDK / 計測 / 新しい敵の追加

## 5. 中止条件

次のいずれかに当たったら、**この案ごと殺して `product/02-ideas.md` の S2 に戻る**（D9・D11）。

- 実働2週間で最小形に届かなかった
- 5人中3人が、促されずに2回目を始めなかった（G2 不通過）
- 5人が説明なしにルールを理解できなかった、または3分以内に誰もゴールに届かなかった（C4 不通過）
- 既存作（Eldergrove / Bouncy Bump）と並べて触らせて、違いが体感されなかった

**粘らないこと。** 落とした17案は理由つきで残してあるので、戻るコストは低い。
