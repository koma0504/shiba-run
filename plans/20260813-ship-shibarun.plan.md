# 実行計画書: 柴犬ランを完成させて公開する

経緯: `product/decisions.md` D12 で「現行の柴犬ランを完成させて出す」方針に決まった。
**ゴールは売上ではなく完走**。指標は「公開できたか」の一点。

初回作の目的として、`research/04-validation.md` 結論5 が言うとおり
「審査・税務・返金・サポート・ストア運用は、出してみるまで一切分からない」。
**これを一度通すこと自体が成果**である。

## 1. 「完成」の定義

**規模を増やして完成を遠ざけない。** 完成とは次の4つがすべて満たされた状態を指す。

- [ ] **終わりがある**。2面をクリアしたらゲームが終わり、終わったと分かる画面が出る
- [ ] **初見が最後まで行ける**。知らない人が投げ出さずに1面をクリアできる
- [ ] **スマホで遊べる**。実機の画面で、まともなレイアウトで遊べる
- [ ] **公開されている**。URLがあり、他人がアクセスして遊べる

3面の追加、ボスの行動パターンの作り分け、音量調整は**完成の条件に入れない**。
出し終えてからの話にする。

## 2. いま分かっている課題（実測）

| # | 課題 | 根拠 | 重さ |
|---|---|---|---|
| 1 | **エンディングがない** | 2面クリア後どうなるか未確認。「終わったと分かる」が完成の条件 | 必須 |
| 2 | **初見の難易度が高い** | 素人操作で開始5秒のうちにHPが6→2まで減った（実ブラウザで実測） | 必須 |
| 3 | **モバイルのレイアウトが画面の1/3しか使っていない** | 390×844の画面で、canvas下端が y=280 付近。下2/3が空白 | 必須 |
| 4 | 画面比が4:3（640×480） | ポータルは16:9レスポンシブを求める | CrazyGames提出時 |
| 5 | ポータルSDKの組み込み | 広告フック・ローディング通知 | CrazyGames提出時 |

基盤C（セーブ・面セレクト・ポーズ・ミュート）の目視確認は**2026-08-13 に完了**した。
実ブラウザでの自動確認17項目がすべて通っている（§5）。CLAUDE.md の「次にやること」から外してよい。

## 3. 手順

**itch.io を最初のゴールにする。** 費用0円・改修ゼロ・審査なしで、いまのビルドでも置ける。
「公開されている」を最短で満たし、そこから磨く。**先に出してから直す**。

### 第1段階: 出せる状態にする（完成の4条件）

1. **エンディングを作る**。最終面をクリアしたら、終わりだと分かる画面を出す。
   実装は既存のオーバーレイ（`#ov`）に乗せる。canvas に描くとダイジェストが変わるので描かない
2. **初見の難易度を下げる**。1面の序盤（最初の30列程度）の敵配置を見直す。
   `stages/stage1.js` のデータだけを触り、engine 側の数値（重力・HP上限）は変えない。
   **ゲームの挙動を意図的に変えるので、`replay-baseline.txt` の更新が必要**。
   更新前に必ずブラウザで意図どおりか確かめること（CLAUDE.md の鉄則）
3. **モバイルのレイアウトを直す**。`index.html` の CSS だけで、canvas を画面の縦幅に合わせて広げる。
   JS を触らなければダイジェストは変わらない

### 第2段階: 公開する

4. **itch.io に出す**。HTML5一式を zip で上げる。ページの説明・スクリーンショット・サムネを作る
5. **出したことを記録する**。`product/` に公開URLと日付を残す

### 第3段階: ポータルへ（任意。第2段階まででも「完走」は成立している）

6. **16:9 対応**。`VIEW_W`/`VIEW_H` を変えると全シナリオのダイジェストが変わる。
   面の見え方も変わるので、**バランスの再確認が要る**。ここは重い
7. **CrazyGames の SDK 組み込みと提出**。事前に公式ドキュメントを自分の目で読む（D3 の未確認事項）

## 4. 検証の扱い

- 第1段階の 1・3 は**挙動を変えない**変更。既存4シナリオのダイジェストが**変わらないこと**で守る
- 第1段階の 2 は**挙動を意図的に変える**変更。ブラウザで確認したうえで baseline を更新する。
  **数字を書き換えて通すのは、検証を捨てるのと同じ**（CLAUDE.md）
- 第3段階の 6 は全シナリオが変わる。**変わること自体は正しい**が、
  変更前に `DUMP=` で描画列を取っておき、差分が画面サイズ由来だけであることを確かめる

## 5. 完了済み: 基盤Cの目視確認（2026-08-13）

実ブラウザ（Chromium）で自動確認し、17項目すべて通過。JS例外なし。

| 分類 | 確認したこと |
|---|---|
| ミュート | ボタン表示が切り替わる / localStorage に保存される / リロード後も保持される |
| 面セレクト | 面の数だけボタンが出る / 未クリア時は2面がロックされる / 1面クリア後に開く / 再描画してもボタンが増殖しない |
| 記録 | 自己ベストがタイトルに表示される |
| ポーズ | プレイ中はオーバーレイが消えている / Esc で出る / P でも出る / **ポーズ中は画面が完全に止まる（canvas が1ピクセルも再描画されない）** / Esc で再開できる / 再開後に動き出す |
| モバイル | canvas が画面幅に収まる / 操作ボタンがビューポート内にある |

「ボタンが増殖しない」は CLAUDE.md の罠「DOMスタブの手抜きは嘘の観測を生む」に対応する確認。
実ブラウザで組み直しが正しく効いていることを確かめた。
