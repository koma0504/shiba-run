# （仮称）じぶんログ — 企画書 v0

これは完成した企画書ではなく、**あなたが赤を入れるためのたたき台**。
あなたが話した内容だけを構造に流し込んであり、勝手な機能追加はしていない。
【 】の部分はあなたにしか書けない。埋めるか消すかを判断していくと、それがそのまま企画になる。

---

## 1. ひとことで（エレベーターピッチ）

> ばらばらに消えていく自分のデータ・行動・言葉・思考をひとつの場所に集め、
> **忘れる前に問い直してくれて**、**気づいていないつながりを見せてくれる**、自分専用の記録と復習の仕組み。

【しっくりこなければ書き直す。30秒で他人に説明できる長さを保つこと】

## 2. 未来のプレスリリース（1年後にこう言えたら成功）

> 2027年8月。私はこの1年、Claudeに聞いたことを一度も失っていない。
> 質問は毎週自動でGitHubに集まり、週に数回「先月あなたはこれを知らなかったが、いまは説明できるか？」という
> 問いが届く。答えられなかったものはまた出てくる。答えられたものは消えていく。
> 先週は、3月に調べた○○と先週調べた△△が実は同じ構造だという指摘が届き、そこから□□を作り始めた。

【○○△△□□に、実際に起きたら嬉しい具体例を入れてみる。具体例が思いつかない機能は、実は要らない可能性が高い】

## 3. なぜ作るのか（解きたい問題）

- Claudeに質問した内容は「自分がまだ知らなかったこと」の正確な記録なのに、聞いた瞬間に流れて消えている
- 一度聞いて分かった気になったことを、覚えているか確かめる機会がない
- データ・行動・言葉・思考が場所ごとにばらばらで、あとから横断して見返せない
- 自分では気づけない知識同士のつながりや、「次はこれをやるといい」という示唆を得る手段がない

【他にもあれば足す。逆に「実は困っていない」ものがあれば消す】

## 4. コアループ（この5段階が仕組みの背骨）

```
①集める → ②ためる → ③問われる → ④答える → ⑤つながる・示唆が来る
   ↑                                              │
   └──────── 新しい質問・行動が生まれる ←──────────┘
```

| 段階 | 内容 | 最初の実装（案） |
|---|---|---|
| ①集める | Claudeへの質問を定期的に自動収集 | まずはClaudeの会話ログの取得手段を検証（企画の最大リスク） |
| ②ためる | GitHubリポジトリに自動push、Markdownで蓄積 | 専用リポジトリ1つ。手で読める形式にする |
| ③問われる | 質問を「復習問題」に変換して定期的に出題 | 週2〜3回、少数から。通知経路は検証して選ぶ |
| ④答える | 自分が答える。正誤で次の出題間隔が変わる | 最初は自己申告（覚えてた/忘れてた）で十分 |
| ⑤つながる | 知識同士の結びつけ・行動の示唆 | **最初は作らない**。②が貯まらないと成立しないため後回し |

## 5. やらないこと（スコープの外）

- 他人に使ってもらうこと（ユーザーは自分ひとり。汎用アプリ化は考えない）
- 最初からの完全自動化（手動の工程が残ってよい。続くかどうかの検証が先）
- ⑤（結びつけ・示唆）の初期実装（データが貯まってから）
- 【他に「今回はやらない」と決めたことを足す】

## 6. 夜も眠れない問題（企画を殺しうるリスク）

| # | リスク | 先に確かめる方法 |
|---|---|---|
| 1 | そもそもClaudeの会話履歴を自動で取れないかもしれない | 取得手段の調査と実験（調査結果は plan 参照） |
| 2 | 出題されても自分が答えず、2週間で無視するようになるかもしれない | 作り込む前に、手動運用で2週間「自分が答え続けるか」を測る |
| 3 | 集めることが目的化して、活用されないデータ置き場になるかもしれない | ③④のループを最優先で作り、①②だけの期間を作らない |

## 7. かける時間の上限（アペタイト）

【例: 「最初の検証に2週間・週5時間まで。それで続かなかったら企画を作り直す」のように、
先に上限を切る。上限がないと際限なく作ってしまい、6のリスク3が現実になる】
