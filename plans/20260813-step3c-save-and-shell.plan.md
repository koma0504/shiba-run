# 実行計画書: 基盤C セーブ・面セレクト・ポーズ・ミュート

経緯: 基盤A（敵の登録制）・基盤B（面のデータ化）でゲームの中身は増やせるようになった。
基盤Cは中身ではなく**外側**を作る。遊びを中断できず、記録が残らず、音を消せない状態を解消する。

4項目を1つの計画にまとめるのは、いずれも `S.state` とオーバーレイUIという同じ2箇所へ集中して
手を入れるため。別々に進めると同じ場所を3回作り替えることになる。

## 1. 目的と完了条件

- 目的: 遊ぶ人が中断でき、記録が残り、音を消せて、行きたい面から始められるようにする。
  **ゲーム中の挙動（物理・敵・当たり判定）は1ミリも変えない**。
- 完了条件:
  - [ ] `run` / `boss` / `stage2` の3シナリオが**現行の基準ダイジェストのまま**通る
        （`fcf04b3ca8591907` / `a03a4a8aef1fb72f` / `061ec3b15b90f469`）
  - [ ] 新シナリオ `pause` が `run` と**1文字も違わない**ダイジェストを出す（§2 判断5）
  - [ ] セーブデータの有無でゲーム中の挙動が変わらない（§2 判断3）
  - [ ] `localStorage` が使えない環境でも例外を出さずに動く
  - [ ] ブラウザで4機能すべてを手で確認
  - [ ] 循環参照ゼロ

## 2. 判断記録

| # | 論点 | 選択肢 | 採用 | 理由（却下理由を含む） |
|---|---|---|---|---|
| 1 | ポーズの持ち方 | `S.paused` の別フラグ / `S.state='pause'` | `S.state='pause'` | `S.state==='play'` のガードが既に8箇所ある（game.js・entities4種・main.js）。状態を1つ足すだけで、そのガードが自動的に「ポーズ中は判定しない」になる。別フラグにすると8箇所すべてに `&&!S.paused` を足すことになり、足し忘れが必ず出る |
| 2 | ポーズ中にフレームを進めるか | `step()` だけ止める / `step`・`updateFx`・`S.time++`・`render()` をすべて止める | すべて止める | `S.time` は背景・骨の上下動・HPの点滅を駆動している。止めないと「ポーズ中なのに画面が動く」。さらに `render()` も止めることで、ポーズを挟んでも描画呼び出し列が1件も増えない＝判断5の検証が成立する。canvasは再描画しなければ内容が保持されるので、画面は止まった絵のまま残る |
| 3 | セーブデータがゲーム中の挙動に与える影響 | 残機・スコアの初期値も復元する / 復元しない | **復元しない** | ここが最重要。保存データを読んで初期状態が変わると、リプレイ検証が「実行環境に前回の保存が残っているか」に依存し、決定論が崩れる。保存データが効くのは「タイトルの表示」「面セレクトで選べる範囲」だけに限る。面を始めた瞬間の状態は、セーブがあってもなくても完全に同一 |
| 4 | 保存キーの持ち方 | 面の配列添字 / 面の `id` | `id` | 添字だと面を途中に挿入した瞬間に、他の面の記録がずれて紐づく。`stage1`/`stage2` という `id` は既に面データが持っている |
| 5 | ポーズが挙動を変えていないことの検証 | 目視 / `pause` シナリオを足す | シナリオを足す | 判断2のとおり止めれば、ポーズを挟んだ実行は `run` と**完全に同一の描画列**になるはず。「同じであるべきもの」を機械的に照合できる。CLAUDE.mdの罠「検証していない場所は壊れていても気づけない」への直接の対策 |
| 6 | 面セレクト・ポーズ画面をどこに描くか | canvas / DOM（既存 `#ov`） | DOM | canvasに描くと描画呼び出し列に載り、完了条件のダイジェスト不変が成立しなくなる。既存のオーバーレイ `#ov` は既にDOMで、`ui.js` が textContent/innerHTML しか触っていない。同じ流儀に乗せる |
| 7 | ミュートの実装箇所 | 各 `sfx()` 呼び出し側 / `audio.js` の内部 | `audio.js` の `tone()` に1つゲート | 呼び出し側は20箇所以上ある。音を出す出口は `tone()` ただ1つなので、ここで止めれば漏れない |
| 8 | ミュート状態の保存先 | セーブデータと同じキー / 分ける | 同じキー | 設定と記録を別キーにする理由がない。読み書きの経路が1本で済む |
| 9 | `localStorage` 不在への備え | 使う直前に `typeof` 判定 / try/catch で包む | **両方** | Safariのプライベートブラウジングは `localStorage` が存在したうえで `setItem` が例外を投げる。存在判定だけでは足りない。加えて `tools/replay-check.mjs` のスタブDOMには `localStorage` 自体が無く、モジュール読み込み時に触ると `ReferenceError` で検証が起動すらしない |
| 10 | 検証ツールに `localStorage` を足すか | 足さない（本体側のガードに任せる） / 空のスタブを足す | 空のスタブを足す | ガードだけだと「保存機能が一切動かない経路」しか検証しないことになる。空のスタブなら「保存はするが、毎回まっさらから始まる」状態を再現でき、判断3（保存が挙動に影響しない）を実際に踏んだうえで確かめられる |
| 11 | ポーズのキー割り当て | Esc / P / 両方 | 両方（`Escape`・`KeyP`） | PCの慣習が分かれている。`input.js` の `KEY_MAP` に足すだけなので費用がない |
| 12 | 面セレクトで選べる範囲 | 全面いつでも / クリア済みの次まで | クリア済みの次まで | 全面開放だと「進める」という動機が消える。1面は常に選べる |

## 3. 実施内容

コミットは4つに分ける。1コミット＝1つの意味のある変更。各コミットの後で3シナリオを通す。

### C-1: 保存層（`src/save.js` 新規）

`localStorage` の読み書きをここだけに閉じ込める。他のモジュールは `localStorage` を直接触らない。

```
shibaRun.v1 → {version:1, muted:false, best:{stage1:0,...}, cleared:[...], reached:'stage1'}
```

- `loadSave()` / `saveNow()` を用意し、読めない・壊れている・書けないときは既定値で黙って続行する
- 判断3のとおり、この層は `S` のゲーム進行値には触らない

### C-2: ミュート

- `audio.js`: `tone()` の先頭に `if(muted)return;`、`setMuted()`/`isMuted()` を追加
- `index.html`: 操作ボタン列にミュートボタンを1つ足す
- 起動時に保存値を反映、押したら保存

### C-3: ポーズ

- `state.js`: `S.state` に `'pause'` を追加（値が増えるだけで既存の分岐は変えない）
- `main.js`: ループを「`pause` のときは `step`・`updateFx`・`S.time++`・`render()` をすべて飛ばす」に変更
- `input.js`: `KEY_MAP` に `Escape`/`KeyP` を追加。`play` ⇄ `pause` を切り替える
- `ui.js`: ポーズ用オーバーレイ（再開／面セレクトへ戻る）
- `tools/replay-check.mjs`: `pause` シナリオを追加。途中で数回ポーズ・解除を挟む
- `tools/replay-baseline.txt`: `pause=` を追加（値は `run` と同一になるはず。**ならなかったら止まる**）

### C-4: 面セレクトとセーブの結線

- `ui.js`: タイトルに面の一覧を出す。クリア済みの次の面まで選べる。各面の自己ベストを併記
- `ui.js` `clearGame()`: クリア時に `cleared`・`best`・`reached` を保存
- `main.js`: オーバーレイのボタン処理を面セレクト経由に整理

## 4. 想定されるつまずき（先に潰しておく）

- **`S.best` が全面共通で1つしかない**（`state.js`）。面ごとのベストへ移す。`clearGame()` はDOMしか触らないのでダイジェストには影響しないが、`run`/`stage2` シナリオがクリアへ到達しないことは念のため確認する（3600フレームではボス未討伐のためゴール扉が閉じている）
- **リプレイはSpaceキーでゲームを開始している**（`input.js` の `if(v&&S.state==='title')startGame()`）。面セレクトを入れてタイトルの開始経路を変えると、シナリオがタイトルのまま3600フレーム進んで全滅する。**この経路は残す**（面を選ばずに始めたら1面）
- **ポーズ解除の1フレーム目に入力が漏れる**恐れ。`input.jumpPressed` は押した瞬間に立つフラグなので、ポーズ中に押されたジャンプが解除直後に発火しうる。解除時に入力エッジを消す
