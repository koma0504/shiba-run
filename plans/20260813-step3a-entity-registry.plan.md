# 実行計画書: 基盤A 敵とギミックの登録制

経緯: ユーザーが「面を増やす・セーブ・難易度・敵とギミックを増やす」構想を示し、そのための基盤づくりを承認した。基盤A（登録制）→ 基盤B（面のデータ化）→ 基盤C（進行とセーブ）の順に進める。本計画はそのA。

## 1. 目的と完了条件

- 目的: 敵やギミックを1種類増やすのに4ファイル（生成・更新・描画・配置）を触っていた状態を、1ファイル追加＋登録簿への追記だけで済むようにする。**挙動は変えない**。
- 完了条件:
  - [x] `node tools/replay-check.mjs`（runシナリオ）→ `digest=f95011843bc0462d`
  - [x] `SCENARIO=boss node tools/replay-check.mjs` → `digest=cd260fee42d5feb2`
  - [x] 循環参照ゼロ
  - [x] 新しい敵を1ファイル追加するだけで動くことを実際に試して確認
  - [x] ブラウザで表示・動作を確認

## 2. 判断記録

| # | 論点 | 選択肢 | 採用 | 理由（却下理由を含む） |
|---|---|---|---|---|
| 1 | 敵の定義に持たせる粒度 | 更新のみ / 更新＋描画＋被弾＋生成 | 更新＋描画＋被弾＋生成 | 「その敵に関することは1ファイルを開けば全部ある」が目的。描画だけ別ファイルに残ると結局2箇所を触ることになる |
| 2 | 描画プリミティブ（roundRect等）の置き場所 | render.jsのまま / 専用draw.js | 専用`draw.js` | entities配下が使うため、render.jsに置くと entities → render → entities の循環になる |
| 3 | 当たり判定・ダメージ処理の置き場所 | game.jsのまま / 専用combat.js | 専用`combat.js` | 同上。entities → game → entities の循環を避ける |
| 4 | 更新順・描画順・被弾判定順の扱い | 1つの配列で統一 / 3つに分けて明示 | 3つに分けて明示 | 3つの順序は実際に異なる（砲台→弾→ネコ→カラス / ネコ→カラス→砲台 / 砲台→ネコ→カラス）。1つにまとめると挙動が変わる。暗黙の番号よりも配列を並べる方が読んで分かる |
| 5 | 敵の弾（enemyBullet）を敵として扱うか | game.jsに残す / エンティティにする | エンティティにする | 更新順を「砲台→弾」と明示できる。描画だけはショットの後という特殊位置なので、render.jsから名指しで呼ぶ |
| 6 | `resetAll`の置き場所 | state.jsのまま / 専用reset.js | 専用`reset.js` | state.jsがentitiesをimportすると entities → state → entities の循環になる。「状態の入れ物」と「入れ物を満たす処理」を分ける |
| 7 | プレイヤー中心座標の計算 | 各敵が都度計算 / `S.playerCenterX`に1フレーム1回 | `S.playerCenterX`に1回 | 原作は1フレームに1度だけ計算していた。被弾死で復活位置へ飛んだあとも、そのフレームの残りの敵は死ぬ直前の位置を見る。都度計算にすると死亡フレームだけ挙動が変わる |
| 8 | `stompEnemy`の第2引数 | `isCrow`(真偽値) / `bounce`(速度) | `bounce` | 真偽値だと敵の種類が増えるたびに分岐が増える。跳ね返り速度を敵側が決める形なら定義1ファイルで完結する |

## 3. 実施内容

- 新規: `src/draw.js`（描画プリミティブ）、`src/combat.js`（当たり判定・ダメージ）、`src/reset.js`（初期化）、`src/entities/`（cat, crow, turret, enemyBullet, spring, mover, index）
- 変更: `state.js`（入れ物に専念、`playerCenterX/Y`追加）、`game.js`（step を stepPlayer / stepPickups / stepShots / stepBoss に分割し、敵は登録簿を回す）、`render.js`（敵とギミックの描画を登録簿へ委譲）、`level.js`（移動床の配置データを追加）

## 4. スコープ外（次の段階で扱う）

- ボスは`game.js`に残した。単体で登場条件・アリーナ・HPバーを持ち、他の敵と構造が違う。面ごとに別のボスを置く段階（基盤B）で一緒に扱うのが自然
- 面のデータ化、進行、セーブ、難易度調整、ポーズ、ミュート
