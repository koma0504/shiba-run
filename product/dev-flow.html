開発フローの調査 / 2026-08-13

発売までの7フェーズ

ゲーム会社が何もないところから発売までに辿る道のりと、その各段階に埋まっているゲートとループ。個人開発向けの圧縮版つき。

この文書の読み方

開発フローは工程表ではなく、中止判断の連鎖である。安い工程を先に置き、高い工程へ進む前に必ずゲート（続行／作り直し／中止）を通す。この構造の目的は「作ること」ではなく「安く早く殺すこと」にある。

下の各フェーズは順に並んでいるが、ゲートで落ちたら上流のループへ戻る。一直線に進むことは想定されていない。

出典の扱い。 フェーズ0の内容（ステップ・ゲート・ループ・テンプレート）は出典を取って調べたもので、末尾に一次・二次のURLを挙げてある。フェーズ1〜6の記述は一般的な業界の実務知識として書いたもので、この調査では出典を取っていない。数字を意思決定に使うなら、この2つを区別すること。

全体像

#フェーズ目的主な成果物通過条件（ゲート）
0発案・市場調査誰に何を売るかを決めるワンシート1文で言え、買う人を指せる
1プロトタイプ面白いかだけを確かめる遊べる検証台他人が促されずに2回目を始める
2プリプロダクション量産の設計図を確定する縦切り（完成品質の数分間）残りの作業量と期日が言える
3プロダクション量産する全コンテンツ最初から最後まで通せる
4仕上げ出せる状態にする審査通過ビルド外部の人が詰まらず終われる
5ローンチ出す公開・ストア素材—
6ライブ運用数字を見て直す更新・ポストモーテム—

伝統的な7段階（concept / prototype / greenlight / pre-production / production / live ops / post-production）は、Develop・Deploy・Grow の3段階へ収束しつつあり、prototype と greenlight はほぼ融合しているという報告がある。つまり「プロトタイプを作ってから承認する」のではなく「プロトタイプが承認そのもの」になってきている。

PHASE 0

発案・市場調査

最も安く、最も多くの案が死ぬ段階。ここでの成果物は100ページの仕様書ではなくA4のワンシート1枚でよい。多くのスタジオはプリプロダクションを1ページの文書で始め、プロトタイプがゲームの価値を証明するにつれて詳細を足していく。

各ステップ

S0

制約の確定

使える月数・金額・週あたり時間・撤退ライン・絶対にやらないことを、すべて数字で紙に書く。ここが決まらないと撤退ラインが引けない。

S1

市場調査（棚を選ぶ）

販売先を1つ決め、候補タグの売れ筋を各10本リストアップし、上位・中位を実際に遊ぶ。ジャンル選択は最大のマーケティング判断であり、ここは削ってはいけない。完了の定義は「この棚の客は誰で、いま何を買っているか」を3分間しゃべれること。

S2

アイデア出し（発散）

タイマーを掛けて1案1行で大量に出す。鉄則は、発散と収束を同じ時間に混ぜないこと。 出すときは評価しない。

S3

一次フィルタ（収束）

翌日、G1のチェックリストを1案10分で機械的に適用する。落とした案は理由を1行ずつ書いて残す。後で戻る先になる。

GATE 1

コンセプト・ゲート

1案あたり10分で判定する。すべて満たせば通過。1つでも欠ければ落とす。

  • ハイコンセプトを1文で言える
  • その1文にプレイヤーの動詞が入っている
  • その1文に他にない要素が入っている
  • 買う人を具体的に指せる（「〇〇と△△を遊んだ人」の形で言える）
  • 置く棚（ジャンル／タグ）が決まっており、その棚に自分の規模の成功例がある
  • 自分の技術で作れる（新規に習得が必要な技術が2つ以下）
  • 制約期間の 1/3 以内で「遊べる最小形」に到達できる見込みがある
  • 自分がこの案に半年〜1年飽きない自信がある
  • 30秒トレーラーの絵コンテが12コマ埋まる（見せ場が12個ある）

G1は「既存作がないこと」を検査しない。 通過した案には、別途、同じことをやっている既存作がないかの飽和チェックを掛ける必要がある。

S4

ワンシート・ハイコンセプト・偽トレーラー

A4に1枚。はみ出したら削る。あわせて30秒トレーラーの絵コンテを12コマ描き、発売時のプレスリリースを先に1枚書く。魅力的に書けなければ作らない（Working Backwards）。12コマが埋まらない案は、実装前にここで捨てる。実装前の最も安い関門。

S5

紙プロト／最小プロト

コアループだけを作る。タイトル画面・メニュー・音・演出・セーブは作らない。磨きすぎたプロトタイプは罠で、見た目に投資すると捨てられなくなる。ゲームを良くする最も効果的な方法は、粗いプロトタイプを作って実際に試すこと。

S6

他人に遊ばせる

知り合いでない人に5〜10人。横で黙って観察し、話しかけない。友人は正直な批判をくれない。

GATE 2

FUNゲート — 「面白い」を言葉ではなく行動で測る

観察で測る

  • 誰にも促されずに2回目を始めた人が半数以上いる
  • 「もう1回」と口に出した人がいる
  • 詰まった箇所が全員バラバラではない（＝設計の問題が特定できる）
  • プレイ中に自発的に声が出た（笑い・悔しがり・驚き）
  • 自分から独自の遊び方・攻略を発明した人がいる

逆向きの警報（1つでも当てはまれば黄信号）

  • 「ここが面白いんです」と口頭で説明しないと伝わらない
  • 「グラフィックが入れば面白くなる」と自分が思っている
  • 「もっとコンテンツを足せば面白くなる」と自分が思っている
  • 面白くない気がし始めている

うまくいかなそう／十分に面白くないと感じ始めたら、それはすでにキルすべきだったサインである。

— Supercell「10 learnings from 10 years」

S7

マーケット検証（見た目だけで需要を測る）

絵コンテを動画にしてSNS・コミュニティ・ストアページに出し、数字を取る。ストアページは早く出してウィッシュリストを集める。ただしトレーラーのないストアページは注意持続時間に合わない。カプセル画像・最初の4枚のスクリーンショット・トレーラーを執拗に最適化する。ここがCTRを決め、CTRがアルゴリズムに直結する。

GATE 3

グリーンライト — 作ると決める

作る価値

  • G2を通過している（行動として観察された）
  • ワンシートが1枚に収まっている
  • 偽プレスリリース／トレーラー台本が、自分で読んでもわくわくする
  • 「5分・10分を超えて広がるビジョン」がある（10時間目の楽しみを言える）

売れる見込み

  • 棚（タグ）が確定し、そのタグの直近の売れ筋を10本触った
  • 競合3本に対して「なぜこっちを買うか」を1行ずつ書けた
  • 見た目だけで需要の兆候が出た（ウィッシュリスト／CTR／SNS反応のいずれか）
  • 想定価格 × 想定販売本数 が、投入する期間の機会費用を上回る

完走できる

  • 縦切りを制約期間の 1/3 で作れる計画がある
  • 新規習得が必要な技術が2つ以下
  • 外注／購入が必要なアセットの費用が予算内
  • 撤退条件を日付付きで書いた（例: 「◯月◯日までにWL 1,000未満なら中止」）

撤退条件を先に書くのは、遅い損切りほど苦しくなるから。6人×6ヶ月の損切りは100人×18ヶ月より、心理的にも経済的にも楽である。個人開発は「1人×Nヶ月」なので、Nが大きくなるほど撤退が不可能になる。まだ撤退が苦しくない今のうちにしか書けない。

スコア表を信じすぎない

多くのゲーム企業が堅牢な分析で新規プロジェクトを承認しようとしたが、実績はスプレッドシートの予測に全く近づかなかった（実績と予測は無相関だった）。新規事業をスプレッドシートで分析するのは無価値か、むしろ負の価値を生む。新規事業の実績を正確に予測することは不可能である。

— Lloyd Melnick（分析駆動グリーンライト・プロセスの提唱者自身による結論）

一方で、関係者全員が同席する場に市場データを持ち込み、主観とバイアスを具体的なスコアに変換することを推奨する立場もある。この2つは矛盾しない。スコア表の価値は「予測」ではなく「議論の可視化」にある。 議論相手がいない個人開発では、スコア表よりも上記のような YES/NO の二値チェックリストのほうが機能する。

なお Supercell にはマネジメントによるグリーンライト手続きが存在しない。マイルストーン会議で財務にプロジェクトの存在を正当化する場もなく、チームが自分でキルを決める。承認者が自分しかいない個人開発者に必要なのは、承認の儀式ではなく自分を止める仕掛けである。

フェーズ0の中にある3つのループ

ループ経路要点
A 発散と収束 S1 → S2 → S3 → G1 →（落ちたら）S2 出すときは評価しない。実データの比率は Voodoo 1,000本 → 4本ローンチ（0.4%）、Double Fine 25案 → 4本プロトタイプ（16%）
B コンセプト検証 S4 → S5 → S6 → G2 →（落ちたら）S4 か S2 テストと改善の回数が多いほど良くなる（Rule of the Loop）。1周を短くして周回数を稼ぐことが目的関数。 Double Fine の Amnesia Fortnight は2週間、Supercell のラフプロトは数週間、Voodoo は3〜4ヶ月で新作をローンチする
C 市場との往復 S1 → S4 → S7 → G3 →（落ちたら）S1 完成後のプレスリリースを先に書く。ストアページを先に出す。1週間〜1ヶ月で終わる磨いたプロトタイプ＋小さなランディングページを多数のパブリッシャーとSNSに送る

ワンシートのテンプレート

複数ソースを統合した実用版。A4で1枚に収める。はみ出したら削る。 合格ラインは「誰が見ても30秒以内にゲームの本質を掴める」こと。

ヘッダ（5行以内）

  • タイトル（できればロゴ）／連絡先
  • ハイコンセプト1文
  • ジャンル・タグ（ストアのタグを3〜5個そのまま）
  • 対象プラットフォーム
  • 対象客層（年齢・既プレイ作品で書く。「幅広い層」は禁止）
  • 対象レーティング／想定発売時期／想定価格

本体

  • サマリ（3〜5行）— 何をするゲームか。動詞で書く
  • コアループ（3〜5ステップ）— 「〜する → 〜が起きる → 〜が増える → 最初に戻る」
  • USP 3つ — 他作品にない要素だけ。「面白い」はUSPではない
  • プレイヤーができるクールなこと 3〜5個 — 具体的な動詞で
  • 世界観・トーン・美術の方向（3行＋参考画像2〜3枚）
  • 物語（あるなら）— 発端・中盤・結末を各1行
  • 競合作品 3〜5本 — 実タイトル名。「うちはここが違う」を各1行
  • 想定収益モデル／規模と期間（プレイ時間・開発期間・人数）
  • リスク3つと、それをどう潰すか

GDDはフェーズ0では書かない。「100ページのバインダは死んだ」は「何も書くな」ではなく、形式が変わっただけで必要性は消えていない。中間形式として1ページ1テーマの ten-pager があり、これを書くならG3通過後、プリプロダクションの入口が妥当。

ハイコンセプト1文の型

ハイコンセプトとは「簡潔に述べた前提でピッチできる作品」のこと。極端な例は『Snakes on a Plane』のようにタイトルが前提のすべてを説明しているもの。

型形注意
X meets Y【Xの既知性】meets【Yの既知性】+【舞台/ひねり】XもYも相手が確実に知っている作品でなければ機能しない。近すぎると情報量ゼロ
What if 〜?もし【異常な前提】だったら、【主人公】は【何をする羽目になるか】？『Jurassic Park』＝「恐竜を生き返らせたら何が起きるか」
動詞+対象+ひねり【誰】として【何をする】ゲーム。ただし【一行のひねり】。ゲームはプレイヤーの動詞が売り物。ひねりの部分がUSPそのものでなければならない

自己チェック: その1文を読んだ人が「で、プレイヤーは何をするの？」と聞き返したら不合格。「新感覚」「爽快」「誰でも楽しめる」「やり込み要素満載」はいずれも情報がゼロで、検証もできない。

PHASE 1

プロトタイプ

「面白いかどうか」だけを検証する。 グラフィックもUIもサウンドも捨て、四角と丸で作る。コードは捨てる前提で書く。ここで綺麗に作ろうとするのが典型的な失敗。

検証したい仮説を先に紙に書く。書かずに作ると「なんとなく良さそう」で通してしまう。フェーズ0のS5・S6・G2と実質的に同じ活動であり、近年この2つは融合しつつある。

ゲート: Fun found? 見つからなければ企画を変えるか中止。健全な組織ほど、ここでよく殺す。

PHASE 2

プリプロダクション

最も地味で、最も飛ばされて、最も後で祟るフェーズ。目的は量産の設計図を確定させること。

  • 縦切り（バーティカルスライス）: 製品と同じ品質の数分間を作る。最終アート・UI・音・演出・カメラまで全部入りの「完成品はこう見える」という現物
  • 技術検証（性能・対応端末・通信・セーブ・実績）
  • 制作パイプラインの整備: アセットをどう作りどう組み込むか、ツール、自動ビルド、自動テスト
  • 必要なコンテンツ総量の算出、レベル設計のルール
  • スケジュールと予算の確定 — ここで初めて「いくら・何ヶ月かかるか」が根拠を持って言える

ゲート: 量産にゴーサイン。ここを飛ばして量産に入ると、後半で作り直しが発生して破綻する。

PHASE 3

プロダクション（量産）

全期間の半分以上を占める。確定した設計で、面・敵・キャラ・シナリオ・音を大量生産する。

マイルストーン意味以降のルール
First Playable最初から最後まで一応通せる—
Alpha（feature complete）機能が全部入った原則、機能を追加しない
Beta（content complete）コンテンツが全部入ったバグ修正とバランスのみ（content lock）

並行してマーケティングが始まる。ストアページを早期公開してウィッシュリストを貯め、SNSで毎週進捗を出し、デモを配り、イベントに出る。完成してから宣伝を始めても、露出の蓄積に必要な数ヶ月が間に合わない。

QAが本格稼働し、バグを重要度（出荷不可／直すべき／余裕があれば）で分類する。ここで最も効くのは削る判断で、予定の8割しか終わらないのが常態である以上、何を落とすかを先に決めておく。

PHASE 4

仕上げ

  • プレイテスト: 社外の被験者に触らせ、喋らせずに観察する。チュートリアル離脱率、詰まる箇所、初回起動から「面白い」に到達するまでの時間を測る
  • バランス調整、難易度曲線、チュートリアル改修（初心者の脱落はほぼここ）
  • ローカライズ（テキスト抽出 → 翻訳 → 組み込み → 現地チェック）
  • 実機性能の最適化、クラッシュ率の追い込み
  • レーティング審査（CERO / ESRB / PEGI、モバイルは IARC）
  • Release Candidate → ゴールドマスター
  • プラットフォーム審査: コンソールは lotcheck で規約準拠を厳格に見られ、通らなければ差し戻し。モバイル・PCストアにも審査がある。数日〜数週間かかる前提でスケジュールを引く
  • 審査後に見つかったバグ用の Day 1 パッチ
PHASE 5

ローンチ

ストア素材が売上を決める。

  • アイコン（モバイルはこれだけでCTRが数倍変わる）
  • スクリーンショット1枚目（何のゲームか2秒で伝わるか）
  • トレーラー: 最初の5秒が全て。 ロゴから始めるトレーラーは負ける
  • 説明文とキーワード（ASO／ストアタグ）
  • プレス・配信者へのキー配布、レビュー解禁日（エンバーゴ）の設定

モバイルF2Pはソフトローンチを挟む。小規模市場で先行配信して継続率と収益性を実測し、数字が悪ければ本配信前に作り直すか畳む。

PHASE 6

指標意味

個人開発向けの圧縮版

フェーズ0の1周で実働3〜6週間。これを最大2〜3周する。1周ごとに1案を殺すか次に進めるかを必ず決める。

#ステップ実働やること完了の定義
0制約を書く1時間使える月数／金額／月あたり時間／撤退ライン／絶対にやらないこと5項目すべてに数字が入っている
1棚を選ぶ2〜3日販売先を1つ決め、候補タグ5個の売れ筋を各10本並べ、上位5本・中位5本を実際に遊ぶその棚の客と現状を3分しゃべれる
220案出す半日タイマー90分。1案1行。評価禁止20行ある
33案に絞る1時間G1を1案10分で機械的に適用3案以下＋落とした理由が1行ずつ
4ワンシート半日×案数テンプレートをA4 1枚に1枚に収まっている
5偽トレーラー半日絵コンテ12コマ（棒人間可）＋発売時プレスリリース1枚12コマ埋まった＆自分で読んで面白い
6紙プロト1〜2日コアループだけを紙・カード・表計算で手回し自分が3回連続で回した
7最小プロト1〜2週間コアループのみ実装。タイトル・メニュー・音・演出・セーブは作らない他人に説明なしで渡せる
8他人テスト2〜3日知り合いでない5〜10人。横で黙って観察5人以上のログがある
9G2 判定1時間G2チェックリストを正直に埋める通過 or 殺す。両方あり得る前提で臨む
10市場検証3〜5日絵コンテを動画にしてSNS・コミュニティ・ストアページへ反応の数字が1つ以上ある
11G3 判定1時間G3チェックリストを埋め、撤退条件を日付付きで書くグリーンライト or 1周目に戻る

圧縮するときに削ってよいもの・いけないもの

判断対象根拠
削ってよい詳細なGDD、ピッチデッキ、財務モデル、綺麗な資料プリプロは1ページから始めるのが主流
削ってよいプロトタイプの見た目・音・メニュー磨きすぎたプロトタイプの罠
削ってよい承認会議、スコアリング表Supercellにはグリーンライト手続き自体がない。スコア表の予測精度は実証されていない
削ってはいけない市場調査（棚選び）ジャンル選択は最大のマーケティング判断
削ってはいけない他人（友人でない）へのプレイテスト友人は正直な批判をくれない
削ってはいけない撤退条件を先に書くこと遅い損切りほど心理的・経済的に苦しい
削ってはいけない案を2本以上走らせること比較対象がないと「これしかない」で判断が歪む
