# 柴犬ラン 5

柴犬を操作して骨を集め、ボスネコ「ニャン大将」を倒して犬小屋を目指す横スクロールアクションゲーム。
HTML Canvas と素の JavaScript だけで作られており、外部ライブラリもビルドツールも使いません。

## 遊び方

開発サーバを起動して <http://localhost:8765> を開きます。

```bash
node tools/serve.mjs
```

ES モジュールを使っているため、`index.html` をファイルとして直接開いても動きません。必ずサーバ経由で開いてください。

| 操作 | キーボード |
|---|---|
| 移動 | ← → （A / D） |
| ジャンプ | スペース（空中でもう一度押すと2段ジャンプ） |
| ショット | Z / X（長押しでチャージショット） |
| ポーズ | Esc / P |

画面下のミュートボタンで音を消せます。設定は次に開いたときも残ります。

画面下のボタンでも操作でき、スマートフォンのタッチにも対応しています。

## ゲームの仕組み

- **HP制と残機制**: HPは6、残機は3（最大5）。ダメージを受けると無敵時間とノックバックが発生します
- **骨**: 50点。20本集めるごとに残機が1つ増えます
- **肉**: 一定時間の無敵状態になり、HPが全回復します
- **コンボ**: 着地せずに敵を連続で踏むと得点が倍々に増えます
- **中間地点**: 4か所。到達済みならそこから再開します
- **ボス戦**: 専用エリアでカメラが固定され、ジャンプ・3方向弾・小刻みなホップの3パターンで攻撃してきます

## コードの構成

`src/` 配下に分かれています。依存は一方向で、循環参照はありません。

| ファイル | 責務 |
|---|---|
| `config.js` | 画面サイズ、タイルサイズ、HP上限などの定数 |
| `canvas.js` | 描画対象の canvas 要素と 2D コンテキスト |
| `draw.js` | 角丸四角・三角など描画の下請け |
| `audio.js` | Web Audio による効果音の合成（音声ファイルなし） |
| `save.js` | 記録と設定の保存。`localStorage` に触るのはここだけ |
| `stage.js` | いま読み込んでいる面の置き場と読み込み処理 |
| `stages/` | 面の定義（1面につき1ファイル） |
| `state.js` | 可変状態オブジェクト `S` |
| `reset.js` | ステージ開始時の初期化 |
| `fx.js` | パーティクルとスコア表示 |
| `combat.js` | 当たり判定・ダメージ・撃破処理（敵と共有） |
| `input.js` | キーボード・ボタン・タッチの入力処理 |
| `ui.js` | オーバーレイ表示とゲーム進行（開始・ゲームオーバー・クリア） |
| `entities/` | 敵とギミック（下記） |
| `game.js` | 毎フレームのゲームロジックとボス |
| `render.js` | 背景・地形・HUD の描画 |
| `main.js` | 各モジュールの配線とゲームループ |

面を作りたいときは `stages/`、面によらない挙動を調整したいときは `config.js` を見てください。

可変状態を単一のオブジェクト `S` にまとめているのは、ES モジュールの import 束縛が再代入できないためです（`import {score}` したうえで `score++` はできません）。

## 敵やギミックを増やす

`src/entities/` にファイルを1つ足し、`src/entities/index.js` の配列に加えるだけです。他のファイルを触る必要はありません。

1ファイルの中に、その敵に関することがすべて入ります。

```js
export default {
  key: 'なまえ',
  group: 'S に置く配列名',
  spawnAll()      // 配置データから初期状態の配列を作る
  update()        // 毎フレームの更新。倒れたあとの削除も自前で行う
  hitByShot(shot) // ショットが当たったか。当たったら true を返す
  draw(camI)      // 描画。画面外の間引きも自前で行う
};
```

ギミック（バネや移動床のようにプレイヤーの移動へ割り込むもの）は、`update` の代わりに次のどれかを持たせます。

| フック | 呼ばれるところ |
|---|---|
| `advance()` | フレームの先頭。自分の位置を動かす |
| `beforeTileY()` | プレイヤーが縦に動いたあと、地形に押し戻される前 |
| `afterTileY()` | 地形に押し戻されたあと。足場として上書きしたいとき |

`index.js` の配列は、並び順がそのまま更新順・当たり判定順・描画順になります。順序を変えると挙動が変わる（＝リプレイ検証が落ちる）ので、意図して並べてください。

## 面を増やす

`src/stages/` にファイルを1つ足し、`src/stages/index.js` の `STAGES` に加えます。既存の面や engine 側のコードは触りません。

面の定義には次を書きます。

| 項目 | 内容 |
|---|---|
| `cols` | 面の長さ（タイル数）。面ごとに違ってよい |
| `timeTarget` | タイムボーナスの基準秒数。短いほど厳しい |
| `theme` | 空・太陽・山・丘・地面・草の色。面の雰囲気を決める |
| `terrain` | `[開始列, 終了列, 開始行, 終了行]` の配列。塗った範囲が地面になる |
| `bones` | `[開始列, 終了列, 行]` の配列。範囲に骨を1つずつ並べる |
| `meats` | パワーアップの肉の座標 |
| `spawns` | 敵とギミックの配置。キーは `entities` の登録名。置かない種類は書かなくてよい |
| `checkpoints` / `goalX` | 中間地点とゴールの座標 |
| `arenaLeft` / `arenaRight` | ボス戦でカメラと移動が固定される範囲 |
| `boss` | ボスの名前・出現位置・体力。面ごとに変えられる |

面を足したら、`tools/replay-check.mjs` にその面のシナリオも足してください。検証していない面は、壊れても気づけません（1面のボスが長く動かないままだったのは、まさにこれが理由でした）。

## 挙動が変わっていないことの検証

```bash
node tools/replay-check.mjs
```

Node 上の疑似 DOM でゲームを自動プレイし、Canvas への描画呼び出し列をハッシュ化します。乱数は固定シード、時刻は固定刻みなので、何度実行しても同じ結果になります。

シナリオは4つあります。面を増やしたら、その面のシナリオも足してください。

```bash
SCENARIO=boss node tools/replay-check.mjs
```

| シナリオ | 内容 |
|---|---|
| `run` | 1面を頭から走る |
| `boss` | 1面のボスアリーナ手前から始める（`run` はボスまで届かないため） |
| `stage2` | 2面を頭から走る |
| `pause` | `run` と同じ操作を流しながら、途中で3回ポーズを挟む |

`pause` の基準値は `run` とまったく同じです。ポーズ中はフレームを1つも進めず描画もしないので、
途中で何度止めても描画呼び出し列は変わらないはずだからです。値が割れたら、ポーズが素通しになっているか、
再開時に入力か時間が漏れています。

ポーズが効くのは遊んでいる最中だけなので、止める位置は「ゲームが進んだフレーム数」で指定します。
生のフレーム番号で書くと前のポーズの長さだけ後ろがずれ、ゲームオーバー画面を止めようとして
黙って素通りします。止めたつもりで止まっていなければ検証が止まるようにしてあります。

座標は小数6桁に丸めて記録します。`Math.sin` のような関数は CPU のアーキテクチャによって最終1ビットが変わるため（arm64 の Mac と x64 の Linux で実測）、丸めないと環境が違うだけで一致しなくなります。

リファクタリングの前後でこのダイジェストが一致すれば、見た目に現れる挙動は変わっていません。重力を `0.55` から `0.5501` に変えるだけで検出できる程度には厳密で、変数名の変更では反応しません。

ゲームロジックを意図的に変更したときは、ブラウザで意図どおりかを確認したうえで基準ダイジェストを更新してください。
